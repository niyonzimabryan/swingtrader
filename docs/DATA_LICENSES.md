# Data licences — what may be committed, what lives only in Postgres

The repo is public and git history does not forget. This file maps each data
source to what may be written into the repository and what may only exist in the
database. It is the reference the Spec K §3.3 CI check enforces, and it is meant
to be read **before** a data-bearing file is committed, not after.

## The rule that overrides everything else

> `research/` holds narrative, sourced claims and *summary* figures that cite a
> cohort id — **never a raw series, never a vendor table, never a news body or a
> news-derived feature.** (Spec K §3.3)

Two mechanisms enforce it, because there are two failure classes: a CI check
fails on a numeric column longer than a handful of rows under `research/`, and
the export itself filters by provenance so that news- and vendor-tier content
never reaches a file. The same prohibition applies to anything else committed to
this repo — the rule is about the repository being public, not about the
directory name.

## Cost ceiling

Data subscriptions are capped at **$100/month** (README §3). The current stack is
Railway Pro $20 + ~$10–20 overage + Sharadar Prices $9 ≈ $40–50/month. Adding a
paid source retires one or is an explicit owner decision.

## Before Sharadar is paid for

Two things, in this order:

1. Confirm what the "$9/mo **from**" tier gates — history depth, request volume,
   or both — and read the redistribution terms. Update the Sharadar row above.
2. Run `python -m scripts.audit_delisting_returns --source sharadar` and record
   the result on the snapshot (Spec N §4.2). A file that stops at the last quote
   instead of carrying the collapse is still usable, but every terminal return
   then has to be synthesised at Shumway's -30% / -55%, and that is a different
   product from the one the marketing copy describes.
